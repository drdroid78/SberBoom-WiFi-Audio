# SberBoom Wi-Fi Audio — окончательный план реализации и сборки APK

## Цель и рамки
Android 10+ (API 29), управление собственным SberBoom и передача аудио телефона по штатному Wi-Fi/SberCast. Без Bluetooth, ROOT, изменения прошивки, промежуточного ПК при эксплуатации, обхода авторизации, чужих токенов и платных API. Один проект, один APK, не привязывать код к модели телефона. Проверка на iQOO Neo 10 и физическом SberBoom. Сборки APK исключительно GitHub Actions. Ghidra 12.2, ее кеш, workflow и сохраненные проекты не изменять.

## 1. Закрыть критическую зависимость: авторизация
Сначала физическая проверка существующего клиента и штатных возможностей аккаунта/устройства. PIN-сопряжение, GetMetaData, громкость проверить отдельно от аудио. PIN не считать заменой backend JWT. В Ghidra найдены JWTSignerServiceImpl::signJsonWebToken 0x01c156c0, generateTokenImpl 0x01c15cc8, getCachedToken 0x01c160e8, SmartAppServiceImpl::getStarosAuthTokenWithUserToken 0x01505734 и BackendServiceImpl::getStarosAuthTokens 0x0167e2e8. Наличие внутренних функций не подтверждает доступ стороннему клиенту и не доказывает, что полученный ими токен дает право на StartStreaming.
Использовать только документированный/разрешенный владельцу способ авторизации Sber. Проверить назначение токена, срок, права и разрешение реальной колонки; автоматическое обновление только при наличии официально доступного механизма. Не имитировать доверенное устройство, не извлекать приватные ключи и не обходить проверку. Если допустимого способа нет — зафиксировать блокер; APK можно собрать для управления и диагностики, но нельзя назвать Wi-Fi-аудио рабочим. Не гонять новые Ghidra-поиски вместо этой проверки.

## 2. Доработки в существующем Kotlin-приложении

|---|---|

| protocol/Protocol.kt, SberBoomClient.kt | Полный PIN flow по фактическим ответам: op=4 и при необходимости явная отправка ConfirmPinConnect op=6. Сейчас обработчик ответа op=6 есть, отправки подтверждения нет. Уточнить jwt_interval_sec и обновление только по подтвержденной схеме. WSS: валидировать подлинность колонки до передачи токенов; убрать trustAll/hostnameVerifier=true, использовать штатную проверку или проверяемое пользователем закрепление сертификата. Сопоставлять ответы по ID/типу/сессии; убрать единственный общий starCommandWaiter, который может принять чужое событие или конкурировать с Alive. |
| data/AppPrefs.kt | Стабильный clientId, настройки, профиль конкретной колонки; токены хранить в защищенном хранилище на основе Android Keystore, не писать их в логи/репозиторий. Раздельные PIN и JWT, явный выход/забыть сопряжение. |
| UI | Русский/английский, список устройств, статус подключения, имя/модель/версия, громкость/mute, play/pause/next/prev где поддерживаются штатным протоколом, источники звука, диагностика, настройки, управление стереопарой/группой. В Protocol.kt уже имеются mediaAction constants, но полноценный UI/клиент для них не реализован. Не обещать поддержку конкретной команды без проверки ответа устройства. |
| audio/PcmSource.kt, OpusEncoder.kt | Сохранить тестовый тон, выбор локального файла через SAF и системный AudioPlaybackCapture с разрешением MediaProjection, PCM16 stereo 48 kHz, корректный ресемплинг/границы кадров и освобождение ресурсов. Opus 20 ms (960 сэмплов/канал), 64 kbps как исследованный стартовый профиль. Захват только приложений, разрешающих его Android; защищенный/запрещенный звук не обходить. |
| audio/UdpPacket.kt, UdpAudioSender.kt | Сохранить проверенный профиль без FEC: LE sequence + LE timestamp + Opus, переменный размер пакета; timestamp по реальной длительности кадра. Тестировать wrap-around, поврежденные пакеты, паузы, потери, исходящий интерфейс и UDP-порт. FEC Reed–Solomon/XOR подключать только после подтверждения согласования параметров; не заявлять универсальный пакет 176 байт. |
| audio/StreamEngine.kt | Не отправлять поток без разрешенной авторизации; не показывать Streaming/«Играет» только после локального запуска энкодера. Отдельные состояния: Discovered, Connected, Paired, Authorized, Negotiating, SendingUnconfirmed, PlayingConfirmed, Reconnecting, Error, Idle. Подтверждение по ответу/событию правильной сессии и тесту звучания. Обработать Start/Stop/Alive/Dead, смену канала, таймауты, исключения, обрыв сети, окончание файла. Повторная сессия только после проверки предыдущей; не выдавать отправку пакетов за звук. |
| Синхронизация/группы | На основе StartStreaming (settings=1, mono_timestamp=2, synced_masters=3), StarPTP 0x9F и DeviceGroup/SberCast Leader. Сейчас monoTimestamp=0 и synced_masters отсутствует. Восстановить точные единицы времени/формат полей и требования к одиночному устройству по штатному обмену, не подставлять выдуманный timestamp. Проверить стереопару отдельно от одиночной колонки: L/R, синхронный старт/стоп, рассинхронизация, переподключение. |
| service/StreamingService.kt | Foreground service с корректными типами MediaProjection/mediaPlayback, разрешения Android, управление уведомлением, wake/wifi locks и освобождение ресурсов, остановка при отзыве разрешения, выключенном источнике или выходе. Экран погашен, переключение приложений, входящий звонок, Wi-Fi восстановление. Проверить реальное поведение autoReconnect, которое сейчас сохраняется в prefs, но отсутствует в Config движка. |
| Диагностика | Сохранить журнал, SSDP/проверку сети и JWT info (метаданные, не проверка подписи). Не считать открытый порт или отправленный UDP доказательством поддержки аудио. Редактировать персональные данные и токены в экспорте журналов. |

## 3. Тесты до сборки
Сохранить существующие 11 Python + 18 Kotlin тестов. Добавить регрессии: PIN подтверждение, неверный/просроченный токен и запрет старта, отказ TLS/изменение сертификата, корреляция ответов и параллельный Alive, таймаут StartStreaming и отсутствие ложного Playing, PTP сериализация по проверенным вектором, UDP wrap/Opus длительности, resampling и EOF, reconnect/stop и очистка ресурсов. Для Android API — инструментальные тесты; эмулятор не заменяет колонку. Все тесты должны проходить до APK.

## 4. Единственная сборка через GitHub Actions
Импорт существующего Android-проекта в корень drdroid78/SberBoom-WiFi-Audio, сохранив README и исследовательские документы. Если исходники содержат конфиденциальные данные, очистить перед публикацией; не добавлять проприетарную прошивку, дампы или credentials. Использовать отдельную ветку разработки и PR. Не менять Ghidra-Cloud.
Зафиксировать Gradle wrapper 8.9 и SHA256 официального дистрибутива, AGP 8.5.2, Kotlin 2.0.20, JDK 17, compileSdk/targetSdk 34, minSdk 29, build-tools 34.0.0 — существующие значения. Не обновлять зависимости беспричинно. Добавить Android CI в .github/workflows/android.yml только после импорта источников. Runner ubuntu-latest, permissions contents:read, ручной workflow_dispatch и pull_request, настройка Temurin 17, Android SDK, Gradle cache; используемые GitHub Actions закрепить проверенными commit SHA. Порядок команд:
```bash
sdkmanager 'platforms;android-34' 'build-tools;34.0.0' 'platform-tools'
chmod +x gradlew
python3 -m unittest discover -s testclient -p 'test_protocol.py' -v
./gradlew --no-daemon :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
"$ANDROID_HOME/build-tools/34.0.0/apksigner" verify --verbose app/build/outputs/apk/debug/app-debug.apk
"$ANDROID_HOME/build-tools/34.0.0/aapt2" dump badging app/build/outputs/apk/debug/app-debug.apk
sha256sum app/build/outputs/apk/debug/app-debug.apk
```
CI сохраняет APK, SHA-256, тестовые XML, lint, итог сборки; успешный APK публикуется как Actions artifact. Для установки по adb использовать скачанный APK. Release-подпись только отдельным ключом владельца, никогда не добавлять ключ в репозиторий. При отказе любого теста сборку не маркировать готовой. Версию повышать при выпуске проверенной сборки.

## 5. Приемка на телефоне и колонке (Codex + владелец)
Телефон и SberBoom в одной Wi-Fi сети, Bluetooth выключен, ПК не участвует в передаче. Установить APK из Actions. Проверить обнаружение и ручной IP, PIN кнопкой +, сохранение после перезапуска, чтение состояния/метаданных, громкость и media-команды. После штатной авторизации: тон, локальный файл, звук стороннего приложения с разрешенным playback capture, stop/pause/resume, смена источника. Зафиксировать фактический звук, состояние сессии и журнал без токенов. Затем экран выключен, 30 минут непрерывной передачи, потеря Wi-Fi/возврат, восстановление, освобождение ресурсов, стереопара/группа (при наличии двух устройств). Если тест не пройден — исправлять конкретный дефект и повторять только необходимые сценарии.

## Критерий конечного результата
Не отчет Ghidra и не успешная компиляция: одна проверенная APK, устанавливаемая на телефон, со всеми согласованными функциями и реальным звуком на SberBoom по Wi-Fi, без обхода штатной авторизации. Ссылка на успешный Actions run, APK, SHA-256, тесты и чек-лист аппаратной приемки. На 27.11.2026 этот критерий еще не выполнен: штатный доступ к аудио JWT и физический тест отсутствуют. Если штатный доступ недоступен, честно обозначить предел осуществимости, не выпускать фиктивную рабочую Wi-Fi-аудиосборку.
